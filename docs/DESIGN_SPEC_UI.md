**目标读者：产品设计、UI 研发人员**

## 1. 设计理念

### 1.1 灵感来源

本规范的设计哲学受以下启发：

| 来源 | 借鉴的核心理念 |
|------|--------------|
| **Apple Human Interface Guidelines** | 清晰 (Clarity)、遵从 (Deference)、纵深 (Depth)；UI 让位于内容 |
| **IBM CUA (Common User Access)** | 键盘驱动导航的工业标准（→、←、↑、↓、Enter、Esc） |
| **Debian raspi-config** | 同生态系统的终端菜单范式 |
| **fzf / Homebrew** | 现代 CLI 的极简美学——无需装饰即可优雅 |
| **Vim / Midnight Commander** | 经受数十年考验的 TUI 交互模式 |

### 1.2 六项核心原则

```
原则 1：UI 即是内容（2026-11-09 修订）
──────────────
界面本身不应吸引注意力。用户看到的是功能、状态和将要发生的改动。
框线只用于划分信息区（信息框/分类/功能/预演），不做装饰；
没有 ASCII 艺术、没有花哨符号。
```

```
原则 2：一屏看全，焦点唯一（2026-11-09 修订）
──────────────
一屏同时给出"有哪些功能、各自现在什么状态、执行会改什么"，
但任一时刻只有一个高亮焦点；用户的目光应自然落在焦点行与预演上。
```

```
原则 3：克制的颜色
──────────────
颜色是路标，不是装饰。一个屏幕上一眼可见的颜色不超过 2 种。
大多数文字保持终端默认色——只有需要用户注意的元素才着色。
```

```
原则 4：呼吸感
──────────────
空白是设计元素，不是浪费。恰当的留白降低认知负荷，
让长时间操作不疲劳。在 80×24 的终端上，留白比填充更珍贵。
```

```
原则 5：即时反馈
──────────────
每一次按键都应得到视觉响应。没有延迟感、没有闪烁、
没有"我按了吗？"的疑虑。切换应平滑如苹果手机的滚动。
```

```
原则 6：无处不在
──────────────
同一套设计语言覆盖主菜单、子菜单、对话框、日志流、确认框。
用户学会一次，终身适用。
```

### 1.3 反模式（明确禁止）

> 2026-11-09 修订：取消"禁止装饰性边框（box-drawing）"与"禁止默认展示 CPU / 内存 / IP"两条——方案 A 仪表盘用圆角框线分区、在顶部信息框展示系统概况（见 §8）。

以下模式**不得**出现在任何 DebNAS 界面中：

- ❌ ASCII Logo 或艺术字横幅
- ❌ 纯装饰用途的框线、分隔线（框线只允许用于 §8 规定的信息分区）
- ❌ Emoji 或 Nerd Font 图标（例外：分类"⚡ 一键部署"的 ⚡，以及 §8.6 列出的单宽状态符号）
- ❌ 展示作者 / QQ 群 / 内核版本等与操作无关的信息（系统概况仅限 §8.3 所列字段）
- ❌ 为采集概况而联网或执行 `apt update`
- ❌ 彩虹色或多色堆叠
- ❌ `clear` + 全屏重绘（造成闪烁）
- ❌ 数字编号前缀（`1.` `2.` `3.`）
- ❌ 不同模块使用不同输出格式

## 2. 视觉语言

### 2.1 色彩体系

#### 2.1.1 调色板（8-ANSI 标准色）

```
                     暗色终端（主流）          亮色终端
─────────────────────────────────────────────────────
 主文字 (DEFAULT)     亮灰 / 白色              深灰 / 黑色
 标题   (TITLE)       加粗白                   加粗黑
 强调色 (ACCENT)      加粗青 (Bold Cyan)       加粗蓝
 成功   (SUCCESS)     绿色 (Green)             绿色 (Green)
 警告   (WARNING)     黄色 (Yellow)            黄色 (Yellow)
 错误   (ERROR)       红色 (Red)               红色 (Red)
 辅助   (DIM)         标准白                   标准黑
─────────────────────────────────────────────────────
```

> **为什么是 8 色？** 256 色和真彩色在老旧 SSH 客户端、串口控制台、手机 SSH App 上可能不被支持。8 色 ANSI 是 1980 年代至今的最低公共标准。终端自身会根据主题（暗/亮）重新映射这 8 种颜色——我们不做手动 RGB 映射，交给终端。

#### 2.1.2 使用规则

| 用途 | 颜色 | 出现频率 | 示例 |
|------|------|---------|------|
| 页面标题 | 加粗白 | ~1% | `DebNAS` |
| 正文内容 | 标准白 | ~90% | 菜单项名称、说明文字、面包屑 |
| 当前焦点 | 加粗青 | ~5%（仅 1 处） | `>` 符号 + 菜单项文字 |
| 操作成功 | 绿色 | ~3% | `[DONE]` 标签 |
| 操作失败 | 红色 | ~1% | `[ERROR]` 标签、错误原因 |
| 辅助提示 | 标准白 | ~1% | Footer 快捷键提示、版本号、分割线 |
| 警告信息 | 黄色 | ~0.5% | `[WARN]` 标签 |

> 一个屏幕上，除了默认色外，**肉眼可见的颜色不应超过 2 种**。

#### 2.1.3 禁止使用的颜色

- **品红 / 紫色 (Magenta)**：在任何界面均不使用。现有代码中的 `COLOR_MAGENTA` 使用点需迁移到青色。
- **粗体 (Bold)**：仅用于页面标题和当前焦点，其他元素不使用粗体。

### 2.2 间距与对齐

#### 2.2.1 基本单位

以**半角空格**为最小间距单位。所有对齐基于等宽字体假设（终端基本属性）。

```
元素                      间距规则
──────────────────────────────────
Header 上方留白             1 空行
Header 与 Content 之间      2 空行
菜单项之间                  0 空行（紧密列表）
Content 与 Footer 之间      自适应（推到屏幕底部）
Footer 与屏幕底部           0 行（Footer 是最后一行）
版本号在 Footer 下方        0 行（紧贴 Footer）
```

#### 2.2.2 水平布局

```
行号    内容
──────────────────────────────────────────
1       (空)
2       <16 空格>DebNAS                    ← 居中（基于终端宽度）
3       (空)
4       (空)
5       <4 空格>基础配置                    ← 正文左缩进 4 空格
6       <4 空格>管理面板
7       <4 空格>Docker
...     ...
N-4     (空，推到 Footer 上方)
N-3     <4 空格>↑↓ 选择  Enter 确认  Q 退出
N-2     (空)
N-1     <右对齐>v3.0.0
N       (空)
```

> **居中计算**：`padding = (COLUMNS - len("DebNAS")) / 2`，使用 `printf '%*s'` 实现。

### 2.3 符号与图标

| 符号 | 用途 | 说明 |
|------|------|------|
| `>` | 当前焦点指示器 | 单字符、青色、替换 4 空格缩进的第一个字符 |
| （无） | 分隔线 | **不使用任何分隔线字符**。区域划分通过空行（呼吸感）实现 |
| `↑↓` | 方向键提示 | Footer 中组合使用 |
| `[DONE]` | 成功标签 | 绿色，方括号格式 |
| `[WARN]` | 警告标签 | 黄色 |
| `[ERROR]` | 错误标签 | 红色 |
| `[INFO]` | 信息标签 | 默认色或灰色 |
| `[DEBUG]` | 调试标签 | 灰色 |

**禁止使用的符号**：`▶` `→` `★` `●` `◆` `>>` `…`（省略号除外，仅用于截断文本）

## 3. 布局系统

> 2026-11-09 起，§3–§5 描述的是**旧版界面**（回退路径：非 TTY 或 `DEBNAS_UI=classic`）；默认界面见 §8。§3.1.2 模式 B（流式日志）仍用于仪表盘的执行阶段。

### 3.1 屏幕架构

DebNAS 的界面分为两种模式，按场景切换：

#### 3.1.1 模式 A：固定布局（菜单交互页）

当用户处于**菜单导航**（主菜单、子菜单、确认框、结果页等待用户输入）时，使用固定三段式布局：

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
│                                              │
│              Header (固定，2 行)              │
│                                              │
├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
│                                              │
│                                              │
│           Content (可滚动，动态高度)           │
│                                              │
│                                              │
├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
│  Footer ─── 快捷键提示 (固定，底部 1 行)       │
│  Footer ─── 版本号 (固定，底部倒数第 1 行)      │
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

**适用页面**：主菜单、子菜单、确认对话框

Header 与 Content 之间、Content 与 Footer 之间各使用一条单行分割线；菜单项之间不加分割线。

页面内容块宽度固定为 **46 字符**，在终端中整体居中；Header、面包屑、菜单项、Footer 和分割线都在该内容块内对齐，不随终端宽度拉伸。

**渲染策略**：

| 区域 | 渲染时机 | 方法 |
|------|---------|------|
| **Header** | 仅在页面初始化时 | 直接 printf |
| **Content** | 焦点移动时（局部刷新）或页面切换时（全量刷新） | 光标定位 + 覆盖写入 |
| **Footer** | 仅在页面初始化时 | 直接 printf |

> Header 和 Footer 绘制后不再触碰。只有 Content 参与交互期间的刷新。这消除了 `clear` 带来的闪烁。

#### 3.1.2 模式 B：自然流式布局（脚本执行中）

当用户确认操作后、脚本开始**实际执行**时，界面退出固定布局，进入**自然流式输出**：

```
[INFO]  检测系统环境…
[DONE] 系统环境检查通过
[INFO]  更新软件包索引…
[INFO]  安装 Docker Engine (1/3)…
[INFO]  安装 Docker CLI (2/3)…
[INFO]  安装 Docker Compose (3/3)…
[DONE] Docker CE 安装完成
```

- **无 Header、无 Footer** — 日志行随输出向上滚动，行为等同于普通 Shell 脚本
- **不主动清屏** — 菜单内容自然被日志推出屏幕上方，日志信息完整保留
- **执行结束后** — 日志末尾显示 `[DONE]` 或 `[ERROR]` 结果行，短暂停留（约 1 秒），在**当前位置**重绘菜单（不清屏，日志保留在菜单上方，用户可向上滚动回看）

**模式切换流程**：

```
启动
  → clear（仅此一次）
  → 绘制菜单 (模式 A)

菜单 → 用户选择 → Enter
  → 日志直接在菜单下方开始输出（菜单自然滚出屏幕）→ 进入模式 B
  → 脚本执行，日志自然滚动
  → 执行完毕，末尾显示 [DONE]/[ERROR] 结果行
  → ~1s 后，在当前位置重绘菜单 → 回到模式 A
  → 日志保留在菜单上方，用户可向上滚动回看

（全程不清屏，信息零丢失）
```

> **设计理由**：
> 1. **日志是信息资产，不是垃圾**。`[ERROR]`、`[WARN]`、版本号、配置路径——这些是用户需要反复查看的内容。`apt install` 报错后你不会希望终端自动清屏。
> 2. **不清屏比清屏简单**。清屏需要管理时机、区域、光标位置——全是复杂度。不清屏 = 零额外代码。
> 3. **菜单"跟着走"是更好的体验**。执行完后用户视线在屏幕底部（最后一行日志），菜单直接出现在那，无需抬眼神。
> 4. **连续操作形成审计轨迹**。第一次运行的日志在上方，第二次在更上方——向上滚动即可回溯整个操作历史。

### 3.2 Header

#### 3.2.1 规范

```
                        DebNAS
```

- **内容**：仅产品名称 `DebNAS`
- **对齐**：水平居中
- **颜色**：加粗白
- **字体**：无特殊要求
- **禁止**：版本号、作者名、社区信息、Slogan

#### 3.2.2 设计理由

Header 只承担**产品身份识别**一个职责。用户不需要每次看到菜单都被告知"这是什么、谁做的、怎么联系"——这些信息属于"关于项目"菜单项。保持 Header 像一个 App 的标题栏：你知道你在用什么，不需要提醒。

### 3.3 Content

Content 是唯一在交互中变化的区域。根据页面类型，有以下几种 Content 形态：

#### 3.3.1 菜单列表（Menu）

```
    基础配置
    管理面板
    Docker
    网络服务
    下载工具
    媒体服务
    系统工具
    关于项目
```

**规则**：
- 每行一个菜单项
- 左缩进 4 个半角空格
- 标准白，无额外装饰
- 当前选中项：前导空格替换为加粗青 `>` + 该项文字变为加粗青
- 标题区与菜单区之间、菜单区与快捷键区之间各一条单行分割线；菜单项之间不加分割线

**选中态对比**：

```
    基础配置          ← 未选中
    管理面板          ← 未选中
  > Docker            ← 选中（`>` 在缩进位置，整行加粗青）
    网络服务          ← 未选中
```

#### 3.3.2 日志流（Log Stream）—— 模式 B

日志流在**模式 B（自然流式布局）** 下使用。屏幕无 Header/Footer，日志行自然占据全屏，随输出向上滚动。

```
[INFO]  检查系统环境
[INFO]  下载 Docker 组件
[DONE] Docker Engine 安装完成
[DONE] Docker Compose 安装完成
[WARN]  软件源响应较慢，已自动切换备用源
[ERROR] Docker 服务启动失败，请检查 systemd 日志
```

**规则**：
- `[TAG]` + 2 空格 + 消息内容
- 标签对齐（通过固定标签宽度实现——`[INFO]`、`[DONE] `、`[WARN]`、`[ERROR]` 长度统一为 7 字符，不足补空格）
- 只有标签部分着色，消息内容保持默认色
- **输出方式**：直接 `printf`/`echo`，不使用光标定位——与普通 Shell 脚本行为一致

#### 3.3.3 结果展示（Result）—— 模式 B 末尾，不清屏

执行完毕后，在日志流末尾显示结果行，短暂停留后在**当前位置**重绘菜单。日志保留在菜单上方。

```
[INFO]  检测系统环境…
[DONE] 系统环境检查通过
[INFO]  安装 Docker Engine…
[DONE] Docker Engine 28.0.1 安装完成
[DONE] Docker CE 安装完成                          ← 最后一行结果

（~1 秒后，在下方重绘菜单。日志保留在上方，可向上滚动回看）
```

**规则**：
- 成功：末尾绿色 `[DONE]` 行总结
- 失败：末尾红色 `[ERROR]` 行 + 原因简述
- 完成后 `sleep 1` 然后 `ui_screen_init` 在当前位置重绘菜单
- **不清屏**，不丢日志

### 3.4 Footer

#### 3.4.1 规范

```
  ↑↓ 选择  Enter 确认  Esc 返回  Q 退出        v3.0.0
```

#### 3.4.2 结构

```
  [左侧：当前页面可用的快捷键]          [右侧：版本号]
```

| 位置 | 内容 | 颜色 |
|------|------|------|
| 左侧 | 快捷键列表（空格分隔双空格） | 标准白 |
| 右侧 | 版本号 `vX.Y.Z` | 标准白 |

#### 3.4.3 按页面类型的 Footer 变体

Footer 仅存在于**模式 A（菜单交互页）**，模式 B 无 Footer。

| 页面类型 | Footer 快捷键 |
|---------|-------------|
| 主菜单 | `↑↓ 选择  Enter 确认  Q 退出` |
| 子菜单 | `↑↓ 选择  Enter 确认  Esc 返回` |
| 确认框 | `Y 确认  N 取消` |

## 4. 组件规范

### 4.1 组件总览

```
lib/ui/
├── header.sh       — ui_header        (渲染页头)
├── footer.sh       — ui_footer        (渲染页脚)
├── menu.sh         — ui_menu          (交互式菜单)
├── dialog.sh       — ui_confirm       (确认对话框)
│                     ui_alert         (提示对话框)
│                     ui_input         (文本输入)
├── log.sh          — ui_log           (格式化日志行)
├── progress.sh     — ui_progress      (进度指示)
└── layout.sh       — ui_screen_init   (在当前位置绘制菜单布局)
                      ui_screen_clear  (仅启动时清屏，不在执行过程中使用)
```

### 4.2 Menu 组件

#### 4.2.1 行为契约

```
输入：
  · 菜单项列表（字符串数组）
  · 初始选中索引（默认 0）
  · 父级标题（可选，用于子菜单的"面包屑"显示）

交互：
  · ↑ / ↓ — 移动焦点
  · Enter  — 确认选择
  · Esc    — 返回上级
  · Q      — 退出程序（仅主菜单）
  · 数字键  — 快速跳转（不显示在界面上）

  · stdout → 用户选中的索引（0-based），或特殊值：
    - 255 → 用户退出 (Q)
    - 254 → 返回上级 (Esc)
```

### 4.3 Dialog 组件

#### 4.3.1 Confirm（确认框）

用于危险操作前的确认（卸载、覆盖配置等）。


**规则**：
- 标题（操作描述）居左缩进 4 空格
- 可选的辅助说明文字（灰色，第二段）
- 底部操作按钮：`[Y] 确认` 和 `[N] 取消`，青色高亮首字母
- 输入：仅 `Y`/`y` 和 `N`/`n` 有效，不区分大小写
- 默认焦点在 `[N] 取消`（安全默认）
- 上下通过空行实现呼吸感，**不使用装饰性分隔线**

#### 4.3.2 Alert（信息提示）

```
    当前系统不是 Debian 12+，无法继续。

    DebNAS 专为 Debian 12 (Bookworm) 及以上版本设计。
    检测到您的系统：Ubuntu 22.04

    Enter 关闭
```

#### 4.3.3 设计原则

- 对话框不阻断终端（不使用 `dialog` 命令），保持纯 Bash
- 在模式 A（固定布局）的 Content 区域渲染，Header/Footer 保持不变
- 通过空行和缩进区分信息层级，不使用装饰性字符

### 4.4 Log 组件

#### 4.4.1 日志行格式

```
[LEVEL]__消息内容
^^     ^^
│      └─ 2 个空格（固定）
└─ 7 字符宽标签（左对齐，不足补空格）
```

#### 4.4.2 标签规范

| 标签 | 宽度 | 颜色 | 语义 |
|------|------|------|------|
| `[INFO] ` | 7 | 默认/青色 | 普通进度信息 |
| `[DONE] ` | 7 | 绿色 | 操作成功 |
| `[WARN] ` | 7 | 黄色 | 非致命警告 |
| `[ERROR]` | 7 | 红色 | 操作失败 |
| `[DEBUG]` | 7 | 灰色 | 调试信息（仅 `--debug` 模式） |

> **为什么标签用 7 字符宽？** `[ERROR]` 是 7 字符，`[INFO]` 是 6 字符 + 1 空格。统一宽度确保消息文本的起始列对齐，形成视觉上的"表格感"，便于扫读。

#### 4.4.3 日志行示例

```
  [INFO]  正在检查系统依赖...
  [INFO]  下载 Docker Engine (28.0.1)...

  [ERROR] 无法连接到 Docker 镜像仓库 (连接超时)
  [DEBUG] curl exit code: 28, url: https://download.docker.com
```

### 4.5 Progress 组件

用于长时间操作的进度反馈。在**模式 B** 下输出，跟随日志流自然排列。

```
[INFO]  下载中… (1/3) Docker Engine
[DONE] 下载完成 (1/3) Docker Engine
[INFO]  下载中… (2/3) Docker CLI
[INFO]  下载中… (3/3) Docker Compose
```

**规则**：
- 当前正在进行的步骤使用 `[INFO]` 标签
- 已完成的步骤显示 `[DONE]`
- 如需显示进度条，使用 `[=====>    ] 60%` 格式（纯 ASCII，避免 Unicode 块字符的兼容性问题）
- 直接 `printf` 输出，不锁定屏幕布局

## 5. 交互模型

### 5.1 键盘导航（主通道）

```
         ↑
         │ 上一个菜单项
         │
  Esc ←──┼──→ Enter    (←返回 / →确认)
         │
  Q ←────┼────         (退出，仅主菜单)
         │
         ↓ 下一个菜单项
```

| 按键 | 作用 | 适用场景 |
|------|------|---------|
| `↑` / `k` | 焦点上移 | 所有菜单 |
| `↓` / `j` | 焦点下移 | 所有菜单 |
| `Enter` | 确认当前选项 | 所有菜单、对话框 |
| `Esc` | 返回上级 / 关闭 | 子菜单、对话框 |
| `Q` | 退出程序 | 仅主菜单 |
| `Y` / `N` | 确认 / 取消 | 确认对话框 |
| `Ctrl+C` | 中断当前操作，自动返回菜单 | 执行中的任务 |

> **Vim 风格 (`j`/`k`) 兼容**：`j`/`k` 映射到 `↓`/`↑` 是一个低成本、高收益的兼容设计——不影响正常用户，但让 Vim 用户感到被尊重。

### 5.2 数字快捷（隐式通道）

数字键 `1`–`9` 可以直接跳转到对应菜单项，但**数字不在界面上显示**。

```
用户看到：                      用户输入：
    基础配置                        1 → 进入基础配置
    管理面板                        3 → 进入 Docker
  > Docker
    网络服务
```

**适用条件**：
- 菜单项数量在 1–9 之间
- 菜单项 ≥ 10 时，数字快捷键对第 10+ 项不生效（此时仅方向键可用）
- 小尺寸终端（`COLUMNS < 70`）兼容模式下，数字恢复显示（见 §7.2）

> **为什么隐藏数字？** 数字编号是导航的**加速器**，不是视觉标签。有经验的用户在记住编号后可以不看屏幕操作；新用户通过方向键发现功能。这与 Apple 的"键盘快捷键不显示在触控界面上"逻辑相同——不为初学者增加视觉噪音。

### 5.3 焦点移动行为

```
边界行为：
  · 在第一个菜单项按 ↑ → 焦点跳到最后一个（循环）
  · 在最后一个菜单项按 ↓ → 焦点跳到第一个（循环）

子菜单行为：
  · "← 返回上级" 是子菜单的最后一个可选项
  · 焦点可以在它上面，按 Enter 等同于按 Esc

对话框行为：
  · 确认框焦点默认在 [N] 取消（安全默认）
  · ← → 切换选项，Enter 确认
```

### 5.4 反馈原则

| 用户行为 | 系统反馈 | 响应时间 |
|---------|---------|---------|
| 按 ↑ / ↓ | 菜单焦点移动（`>` 移动 + 颜色切换） | < 50ms |
| 按 Enter | 进入子菜单 / 开始执行（Content 区更新） | < 100ms |
| 按 Esc | 返回上级菜单（Content 区更新） | < 100ms |
| 操作完成 | 日志末尾显示 [DONE]/[ERROR] → ~1s 自动返回菜单 | 取决于操作本身 |
| Ctrl+C | 显示中断行 → 自动返回菜单 | < 100ms |
| 无效按键 | **无反馈**（不响、不闪、不提示） | — |

> **"无效按键静默"原则**：这是一个重要设计决策。传统 TUI 常用"哔"声或错误提示响应无效按键——这很烦人。遵循 Apple 的设计哲学：无效操作优雅地什么都不发生。用户会自然尝试正确的方式。

## 6. 技术实现指南

> **本章面向 UI 组件开发者**。如果你不写代码，可以跳过本章，直接阅读附录 A 的视觉示例。

### 6.1 技术选型决策

#### 6.1.1 为什么不使用 `dialog` / `whiptail`？

| 考虑维度 | dialog/whiptail | 纯 Bash + ANSI |
|---------|----------------|---------------|
| 依赖 | 需安装 `dialog` 或 `whiptail` 包 | 零额外依赖 |
| 样式可控性 | 受限于工具皮肤 | 完全可控 |
| 终端兼容性 | 部分终端有显示问题 | 极好（仅依赖基本 ANSI） |
| 与项目理念一致性 | 引入外部工具 | 与纯 Bash 约束一致 |

> **结论**：不引入外部 TUI 工具。使用 ANSI 转义序列 + `tput` 实现所有效果。

#### 6.1.2 `tput` vs 硬编码 ANSI

```bash
# 推荐：tput（可移植）
cursor_hide()  { tput civis 2>/dev/null; }
cursor_show()  { tput cnorm 2>/dev/null; }
cursor_move()  { tput cup "$1" "$2" 2>/dev/null; }

# 回退：硬编码 ANSI（tput 不可用时）
# \033[?25l — 隐藏光标
# \033[?25h — 显示光标
# \033[{row};{col}H — 移动光标
```

**策略**：优先使用 `tput`，回退到硬编码 ANSI。`tput` 读取 terminfo 数据库，理论上在所有 POSIX 终端上都可用。

### 6.2 核心技术实现

#### 6.2.1 单键捕获（含方向键）

方向键在终端中发送的是**多字节转义序列**，不是单个字符：

| 按键 | 转义序列 (ANSI) | 转义序列 (VT-100) |
|------|----------------|-------------------|
| `↑` | `\033[A` | `\033OA` |
| `↓` | `\033[B` | `\033OB` |
| `→` | `\033[C` | `\033OC` |
| `←` | `\033[D` | `\033OD` |
| `Esc` | `\033` | — |
| `Enter` | `\n` 或 `\r` | — |

**捕获实现**：

```bash
# 读取单个键（含方向键识别）
read_key() {
  local key
  IFS= read -r -s -n 1 key
  if [[ "$key" == $'\033' ]]; then
    # 可能是 Esc 或方向键前缀
    local rest
    IFS= read -r -s -n 2 -t 0.001 rest 2>/dev/null || true
    key+="$rest"
    # \033[A → UP, \033[B → DOWN, \033 → ESC
    case "$key" in
      $'\033[A'|$'\033OA') echo "UP";    return 0 ;;
      $'\033[B'|$'\033OB') echo "DOWN";  return 0 ;;
      $'\033[C'|$'\033OC') echo "RIGHT"; return 0 ;;
      $'\033[D'|$'\033OD') echo "LEFT";  return 0 ;;
      $'\033')             echo "ESC";   return 0 ;;
    esac
  elif [[ "$key" == $'\n' || "$key" == $'\r' ]]; then
    echo "ENTER"; return 0
  elif [[ "$key" == "q" || "$key" == "Q" ]]; then
    echo "Q"; return 0
  elif [[ "$key" == "j" || "$key" == "J" ]]; then
    echo "DOWN"; return 0    # Vim 兼容
  elif [[ "$key" == "k" || "$key" == "K" ]]; then
    echo "UP"; return 0      # Vim 兼容
  elif [[ "$key" =~ ^[1-9]$ ]]; then
    echo "NUM:$key"; return 0
  fi
  echo "OTHER:$key"
}
```

> **`-t 0.001` 的超时逻辑**：当读到 `\033` 时，它可能是独立的 `Esc` 键也可能是方向键序列的前缀。`read -t 0.001` 尝试在 1ms 内读取后续字节——如果读到，说明是方向键；如果超时，说明是 `Esc`。

#### 6.2.2 局部刷新策略

这是消除闪烁的核心技术：

```
场景 1：焦点移动 (↑ / ↓)
──────────────────────────
1. 定位到"旧焦点行" → 重写该行为无焦点状态（默认色，`   ` 替换 ` > `）
2. 定位到"新焦点行" → 重写该行为焦点状态（青色 ` > `）
3. 光标回到 Footer 下方（隐藏）

每次焦点移动仅重写 2 行，而非整个屏幕。
```

```
场景 2：页面切换 (Enter 进入子菜单 / Esc 返回)
──────────────────────────────────────────
1. 清空 Content 区域（从 Header 下方到 Footer 上方）
2. 全量渲染新页面内容
3. Header 和 Footer 不重绘
```

**实现方法**：

```bash
# 局部更新单个菜单行
# $1: 行号 (屏幕上绝对行号), $2: 文本, $3: 是否选中
ui_menu_update_line() {
  local row="$1" text="$2" selected="$3"
  tput cup "$row" 0 2>/dev/null || printf '\033[%d;0H' "$row"
  if [[ "$selected" == "true" ]]; then
    printf '%b > %s%b\n' "$COLOR_CYAN" "$text" "$COLOR_RESET"
  else
    printf '   %s\n' "$text"
  fi
}
```

#### 6.2.3 终端尺寸变化处理

```bash
# 捕获 SIGWINCH（窗口大小变化信号）
trap 'ui_handle_resize' SIGWINCH

ui_handle_resize() {
  # 更新缓存的终端尺寸
  COLUMNS=$(tput cols 2>/dev/null || echo 80)
  LINES=$(tput lines 2>/dev/null || echo 24)
  # 全量重绘当前页面
  ui_render_current_page
}
```

**注意事项**：
- SIGWINCH 处理函数中不应进行耗时操作
- 重绘后需恢复光标位置
- `COLUMNS`/`LINES` 是 Bash 内置变量，但仅在交互式 shell 中自动更新——脚本中需手动获取

#### 6.2.4 光标隐藏

```bash
# 初始化时隐藏光标，避免光标在屏幕上闪烁
tput civis 2>/dev/null || printf '\033[?25l'

# 退出时恢复光标（必须在 EXIT trap 中执行）
trap 'tput cnorm 2>/dev/null || printf "\033[?25h"; exit' EXIT
```

### 6.3 组件实现模式

所有 UI 组件遵循统一的调用模式：

```bash
# 模式 A：渲染函数（纯输出到 stdout，无副作用）
ui_header          # → 输出 Header 到 stdout
ui_footer "↑↓ 选择  Enter 确认  Q 退出"  # → 输出 Footer 到 stdout
ui_log "INFO" "正在下载组件..."

# 模式 B：交互函数（处理输入循环，输出结果到 stdout）
selected=$(ui_menu "主菜单" "${items[@]}")
result=$(ui_confirm "确定要卸载 Docker 吗？")
```

**交互函数的输入/输出约定**：

| 方面 | 约定 |
|------|------|
| 渲染输出 | 直接写入 `/dev/tty`（保证即使在管道中也能正常显示） |
| 用户输入 | 从 `/dev/tty` 读取（而非 stdin） |
| 选择结果 | 通过 `stdout` 返回（调用方用 `$()` 捕获） |
| 调试日志 | 写入 `stderr`（不影响 stdout 返回值） |

> **为什么用 `/dev/tty`？** 如果 `ui_menu` 被用在管道中（如 `choice=$(ui_menu ...)`），stdin 会被重定向。直接读写 `/dev/tty` 确保即使在管道中也正常工作。

### 6.4 色彩实现

```bash
# 在 lib/core/colors.sh 中增加灰色
COLOR_DIM=$'\e[0;90m'      # 亮黑 = 灰色
# 移除 COLOR_MAGENTA 的使用（保留定义但标记为 deprecated）

# 在 lib/ui/styles.sh 中修改语义映射
get_ui_color() {

```

### 7.2 小尺寸终端适配

当 `COLUMNS < 70` 或 `LINES < 20` 时，自动切换到**兼容模式**：

```
兼容模式变化：
  1. 恢复数字编号显示 (1. 2. 3. ...)
  2. 去除菜单项间的空行
  3. Header 左对齐（不居中，节省宽度计算）
  4. Footer 双行合并为单行
```

**示例（40×15 手机 SSH）**：

```

3.Docker       4.网络服务
```

> **检测时机**：每次页面初始化时检测一次。同一会话内不动态切换（避免 SIGWINCH 触发的频繁模式切换带来的闪烁）。

### 7.3 NO_COLOR 支持

```bash
# 当 NO_COLOR=1 或 stdout 不是 tty 时，所有颜色变量设为空字符串
# lib/core/colors.sh 已有此逻辑，保持不变
```

无颜色模式下，焦点指示器 `>` 仍保留（纯文本即可区分），但丧失颜色对比。通过缩进差异仍可识别当前选中项。

### 7.4 屏幕阅读器友好

- 所有 UI 文本保持纯 ASCII + 中文，不使用 Unicode 装饰符
- 日志标签使用 `[INFO]`、`[DONE]` 等方括号格式（屏幕阅读器可正确读出）
- 焦点变化时有状态文字输出（可通过环境变量 `DEBNAS_ACCESSIBILITY=1` 启用详细播报模式）

## 8. 方案 A：双栏 TUI 仪表盘（默认界面，2026-11-09）

> 本节为 2026-11-09 新增，是 `bin/menu.sh` 默认交互界面的规范；实现见 `lib/ui/dashboard.sh`、`lib/ui/textwidth.sh`、`lib/ui/sysinfo.sh`，模块状态/预演契约见 [ARCHITECTURE.md §4.5](ARCHITECTURE.md)。

### 8.1 设计原则

```
原则 A1：状态先于操作
──────────────
每个功能旁边都显示它"现在是什么状态"（已应用/运行中/未安装/异常），
用户不必先执行一遍才知道装没装。

原则 A2：先预演，再执行
──────────────
执行前给出将安装的包、将修改的文件（含备份位置）、服务/端口变化和风险（如是否断开 SSH）。
回车后先显示完整预演并要求确认，确认后才离开全屏、流式执行。

原则 A3：只读、快速、不联网
──────────────
仪表盘自身的任何采集（系统概况、模块状态、预演）都必须只读：不 apt update、不写文件、不联网。
系统概况 < 200ms；模块状态并行异步采集，单个超时（3s）只影响该行。

原则 A4：稳定的布局，局部的刷新
──────────────
各框高度按内容分配（§8.2.1）：同一分类内移动焦点时框线不动，切换分类、勾选/预演变化、窗口尺寸变化时重新计算；
每帧整屏合成后与上一帧逐行比对，只重写变化的行——不 clear、不闪烁（帧变短时多出的行被擦成空行）。

原则 A5：可退化
──────────────
窄终端退化为单栏两级；非 TTY / DEBNAS_UI=classic 回退旧版菜单（§3–§5）。
```

#### 8.2.1 行分配（功能栏 / 预演框，2026-11-10）

上方列表框（双栏的"分类 + 功能"、单栏的分类框或功能框）与预演框共用"终端行数 − 固定行"，按内容分配（`_dash_alloc_rows`）：

| 项 | 规则 |
|----|------|
| 功能栏需要的行 | 表头 1 + 当前分类功能数 + 分隔线 1 + 详情 1~3；双栏还要不小于 分类数 + 2（分类 + 空行 + 搜索行）；单栏分类页为 分类数 + 1 |
| 功能栏下限 | 表头 + min(功能数, 5) + 分隔线 + 详情 1 行；双栏还要不小于 min(分类数, 8) + 2；单栏分类页为 min(分类数, 5) + 1。被压到下限时先收详情行，再滚动列表 |
| 预演框最小行数 | 双栏 4 / 5 / 6 行（终端 < 32 / < 36 / ≥ 36 行）；单栏 3 行（终端不足 20 行时不显示预演框） |
| 预演框想要的行 | 已勾选且预演与勾选一致时 = 预演条数；未勾选、未预演或勾选已变化时 = 最小行数 |
| 分配 | 预演框取"想要的行"，但不能把功能栏压到下限以下，放不下时末行显示"另有 N 条"；其余行归功能栏 |
| 双栏 | 功能栏不超过自己需要的行（整体紧凑，帧可以比终端矮）；预演框与快捷键行之间留 1 空行，行数不够时让出 |
| 单栏 | 功能栏占满剩余行，快捷键行固定在最后一行 |
| 重新计算 | 每帧计算；切换分类、搜索、勾选/预演变化、SIGWINCH 后框高随之变化，由逐行比对刷新擦除旧内容 |

例：80×24 单栏、容器管理（3 个功能）勾选两项预演 10 条 → 功能栏 8 行、预演框 10 行全部可见；未勾选 → 功能栏 15 行、预演框 3 行。

### 8.4 左栏：分类

- 第一项固定为 `⚡ 一键部署`（`config/solutions/*.list`），计数为方案数；其余按 `CATEGORY_ORDER`，跳过空分类。
- 计数 `已完成/总数`：`applied` / `running` 计为完成；全部完成时绿色，否则灰色。
- 当前分类前显示青色 `▶`；左栏获得焦点时整行高亮。
- 最后一行固定为 `/ 搜索功能…`（灰）；搜索输入中显示 `/ 关键词▏`（青），确认后显示 `/ 关键词（N 项）`。

### 8.5 右栏：功能列表

- 勾选框：`[✓]`（青）/ `[ ]`（灰）。
- 一键部署分类中每个方案为一行，状态由成员模块汇总（全部完成 / `k/n` 部分完成 / 均未完成），说明为"依次执行：A → B → C"。
- 说明列显示 `module_status` 返回的简短说明；状态未知或检测中时显示模块说明（`@description` 或文件头 `# 功能：`）。
- 右栏获得焦点时焦点行整行高亮；标题为分类名或"搜索：关键词"，右侧"已选 N 项"。

| 按键 | 行为 |
|------|------|
| `↑` `↓` / `j` `k`，`PgUp` `PgDn` `Home` `End` | 在当前栏移动（左栏移动即切换分类，右栏焦点归零） |
| `←` `→` / `Tab` / `Esc` | 切换栏（单栏模式下为返回/进入）；搜索结果中 `Esc` 退出搜索 |
| `空格` | 右栏：勾选/取消并下移一行；左栏：整类全选/全不选 |
| `回车` | 有勾选：执行全部勾选项；无勾选：右栏执行当前项，左栏进入右栏 |
| `d` | 对勾选项逐个调用 `module_plan` 生成预演（只读）；同批先执行的依赖模块不再报"依赖缺失"，改为一条"将先执行依赖「…」"（ARCHITECTURE §4.5.1） |

### 8.9 执行模式

回车后离开全屏（恢复主屏幕与终端设置）进入 §3.1.2 模式 B 流式输出：

```

  1. 配置防火墙 (firewall)
  2. 配置 Fail2ban (fail2ban)
预演
  + 安装  firewalld  apt · 1 个包
  ...

━━ [1/2] 配置防火墙 (firewall) ━━

━━ [2/2] 配置 Fail2ban (fail2ban) ━━

  ✖ 配置防火墙  退出码 3
```

- 一键部署方案按文件顺序展开，与单独勾选的模块合并去重，并按 `@depend_modules` 依赖在前排序。
- 依赖模块在本次执行中失败时，下游模块跳过（不再执行）。
- 成功的条目自动取消勾选；返回仪表盘后只重新采集执行过的模块状态。
- `--yes`（`DEBNAS_FORCE_YES=1`）跳过确认。执行期间 Ctrl+C 只中断当前模块（同旧版）。
- 子进程运行前恢复进入仪表盘前的 locale，模块输出语言不受仪表盘影响。

### 8.10 退化与回退

| 条件 | 表现 |
|------|------|
| 列数 < 100 或 行数 < 28 | 单栏两级：首行概况一行文字 → 分类框（`→`/回车进入）→ 功能框（状态列/勾选/详情 1~3 行，`←`/`Esc` 返回）→ 预演框（行数 ≥ 20 时；最少 3 行，按 §8.2.1 扩展）→ 快捷键行 |
| 列数 < 40 或 行数 < 14 | 提示"终端太小"，仍可 `q` 退出 |
| stdin/stdout 非 TTY、`TERM=dumb`、`DEBNAS_UI=classic`、无法获得 UTF-8 语义 | 回退旧版 `ui_menu` 界面（§3–§5） |
| 窗口尺寸变化（SIGWINCH） | 重新布局并整屏重绘一次 |

### 8.11 技术约束

- 纯 Bash + `tput`（仅取尺寸）+ ANSI；不使用 dialog/whiptail/ncurses 库。
- 备用屏幕 `\e[?1049h`、隐藏光标、`stty -echo -icanon`；EXIT trap 先恢复终端再以原退出码执行原有清理 trap；INT 置退出标志。
- 显示宽度：`ui_str_width` 按码点区分 East Asian Wide/Fullwidth（2 列）、组合/零宽（0 列），其余 1 列；Ambiguous（`●○◐✓…`）按西文终端 1 列处理。当前 locale 非 UTF-8 时切到 `C.UTF-8`，失败则回退旧界面。
- 8 色 ANSI：灰（90）、青、绿、黄、红；焦点行蓝底（44）。焦点行内去掉灰色前景（蓝底灰字对比度低，且部分终端/渲染器会让带亮黑前景的单元格背景与相邻单元格不一致），每个颜色重置后立即重开蓝底，保证整行背景连续（含列间空格）。`NO_COLOR` 时去掉全部颜色，焦点行改为反显（7），勾选框/符号仍可区分。
- 一屏可见颜色数放宽：§2.1.2"不超过 2 种"仅约束旧版界面；仪表盘的颜色只用于状态语义（绿/黄/红）与结构（青标题、灰辅助），不得用于装饰。

## 附录 B：组件 API 契约草案

> 以下为组件函数签名草案，供实现阶段参考。具体参数列表可在编码时微调。

### B.1 布局组件

```bash
# 在当前位置绘制菜单布局（Header + Content + Footer + 隐藏光标）
# 启动时：先由 main() 调用 clear，再调用 ui_screen_init
# 执行后：直接调用 ui_screen_init（不清屏，在当前位置绘制，日志保留在上方）
# 参数：无
# 全局依赖：$COLUMNS, $LINES, $DEBNAS_VERSION
ui_screen_init

# 渲染 Header
# 输出：居中显示 "DebNAS"
ui_header

# 渲染 Footer
# 参数：$1 — 快捷键提示字符串
# 输出：左侧快捷键（灰色）+ 右侧版本号（灰色）
ui_footer "↑↓ 选择  Enter 确认  Q 退出"
```

### B.2 菜单组件

```bash
# 交互式菜单
# 参数：
#   $1          — 面包屑标题（可选，"" 表示主菜单）
#   $2 .. $N    — 菜单项列表（至少 1 项）
# 选项：
#   -b, --back-label LABEL  — 返回按钮文字（默认 "← 返回上级"）
#   -q, --quit              — 启用 Q 退出（仅主菜单）
# 输出 (stdout)：选中的索引 (0-based) 或 255 (退出) 或 254 (返回)
# 交互：↑↓ 导航，Enter 确认，Esc 返回，Q 退出
ui_menu "容器管理" "安装 Docker" "配置镜像加速" "卸载 Docker"
```

### B.3 对话框组件

```bash
# 确认对话框
# 参数：
#   $1 — 标题（操作描述）
#   $2 — 辅助说明（可选，多行用 \n 分隔）
# 输出 (stdout)：0 (确认) 或 1 (取消)
# 交互：Y/N 或 ←→ 选择 + Enter
ui_confirm "确定要卸载 Docker 吗？" "将移除所有容器和镜像。\n正在运行的容器将被停止。"

# 信息提示框
# 参数：
#   $1 — 标题
#   $2 — 辅助说明（可选）
ui_alert "当前系统不是 Debian 12+" "DebNAS 需要 Debian 12 (Bookworm) 或更高版本。"

# 文本输入框
# 参数：
#   $1 — 提示文字
#   $2 — 默认值（可选）
# 输出 (stdout)：用户输入的文本
ui_input "请输入主机名" "debnas"
```

### B.4 反馈组件

```bash
# 日志行
# 参数：
#   $1 — 级别 (INFO/OK/WARN/ERROR/DEBUG)
#   $2 — 消息内容
ui_log "INFO" "正在检查系统环境"
ui_log "OK"   "Docker Engine 安装完成"
ui_log "ERROR" "无法连接到服务器 (超时)"

# 进度步骤
# 参数：
#   $1 — 步骤号
#   $2 — 总步骤数
#   $3 — 描述
ui_progress_step 1 3 "Docker Engine"

# 结果输出（在日志流末尾调用，自动返回菜单）
# 成功：ui_log "OK" "Docker CE 全部组件安装完成" 即可，然后 sleep 1 + ui_screen_init
# 失败：ui_log "ERROR" "Docker CE 安装中断——网络不可达，请检查连接后重试"
# 无需单独的 ui_result_success / ui_result_error 组件——日志行本身就是结果
```

## 附录 C：从当前 UI 迁移指南

### C.1 差异清单

| 当前实现 (v2.x) | 目标设计 (v3.0) | 影响范围 |
|----------------|----------------|---------|
| `print_banner()` 显示作者/QQ/GitHub | `ui_header` 仅显示 `DebNAS` | `bin/menu.sh` |
| 菜单项 `1. 名称` 数字编号 | 无数字、`>` 焦点 | `lib/ui/styles.sh`、`lib/ui/menu.sh`、`bin/menu.sh` |
| `read -r choice` 数字输入 | 方向键导航 + 隐式数字 | `lib/ui/menu.sh`、`bin/menu.sh` |
| `clear` 全屏刷新 | 局部刷新 | `bin/menu.sh`、`lib/ui/menu.sh` |
| `COLOR_MAGENTA` 高亮色 | 迁移到 `COLOR_CYAN` | `lib/ui/styles.sh`、所有使用点 |
| 无 Footer | `ui_footer` 固定底栏 | 所有页面 |
| 模块自行输出格式 | 统一 `ui_log` 组件 | 各模块 |
| 无确认对话框 | `ui_confirm` 组件 | `bin/menu.sh`、需确认的模块 |

### C.2 推荐迁移分批

```
Phase 1 (基础 — 不影响交互)
├── 清理 Header (移除作者/QQ/温馨提示)
├── 增加 Footer (固定快捷键提示行)
├── 调整颜色 (新增 COLOR_DIM、迁移 MAGENTA→CYAN)
└── 日志格式对齐 (增加 [TAG] 前缀)

Phase 2 (核心 — 菜单交互重构)
├── 实现方向键捕获 (read_key 函数)
├── 实现 ui_menu 组件 (方向键导航 + 局部刷新)
├── 重写 bin/menu.sh (对接新菜单组件)
└── 隐式数字快捷键

Phase 3 (扩展 — 对话框和其他组件)
├── 实现 ui_confirm / ui_alert
├── 实现 ui_progress_step
├── 执行完成后自动返回菜单（sleep 1 + ui_screen_init）
└── 各模块日志迁移到 ui_log 统一格式

Phase 4 (打磨 — 终端兼容)
├── SIGWINCH 处理
├── 小屏兼容模式
├── tmux/screen 兼容测试
└── NO_COLOR 回归测试
```

### C.3 兼容性承诺

- `lib/core/colors.sh` 的变量名保持向后兼容（`COLOR_MAGENTA` 定义保留但弃用）
- `lib/core/logging.sh` 的 `log_info` / `log_error` 等函数保留现有签名，内部增加 `[TAG]` 格式化
- `lib/ui/styles.sh` 的 `print_*` 函数逐步替换为 `ui_*` 前缀的组件函数，旧函数标记 `# @deprecated`

> **关键原则**：分阶段迁移，每阶段独立可交付。不进行一次性的"大爆炸"重写。
